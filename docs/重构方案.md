# LightPanel Vue 重构方案

> 目标：在天翻地覆的同时**不丢任何一个现有功能**，且每一步都可独立验证、可回滚。
> 当前基线（已实测）：`npm run test` 32/32 通过，`npm run build` 成功，产物 JS 230 KB / CSS 305 KB（gzip 44 KB）。

---

## 0. 现状诊断（实测数据，非估算）

| 指标 | 实测值 | 问题 |
|------|--------|------|
| 源码总量 | 17,641 行 TS/Vue + 5,999 行 CSS | — |
| 主题 CSS | 4,847 行 / 5,999 行 = **81%** | 单一改动面 |
| 构建 CSS | 305 KB 未压缩 | 首屏白给 |
| 卡片三大家族 | sites 1,877 + docker 2,945 + services 2,366 = 7,188 行 | **41% 代码** |
| 三个 Grid 组件 | 460 + 480 + 466 = 1,406 行，模板近乎逐字相同 | 三份平行实现 |
| 两个布局切换器 | `LayoutSwitcher` 875 + `DataLayoutSwitcher` 665 = 1,540 行 | 只为选一个 enum |
| 主题内 `[data-theme=x] .内部class` 规则 | 每套 ~90 条，覆盖 **124 个组件内部 class** | 主题知道组件私有 DOM |
| `.search-bar-container` 被主题重写 | **80 次** | 组件不拥有自己的皮肤 |
| aria / role 属性 | 9 处 | 基本无无障碍 |
| 单元测试 | 32 个，全是纯函数（siteLinks / groups） | 零组件测试 |

### 三条根因

**R1｜主题是"皮肤文件"，不是"token 契约"。**
`receipt.css` 里写着 `[data-theme="receipt"] .card-title, .list-title, .compact-title, .minimal-name {…}` —— 主题知道每种卡、每种布局的内部 class 名。后果是双向指数耦合：加一个组件要在 9 个主题里各补一遍；加一个主题要认识全部 124 个内部 class。**9 套主题实际是 9 份平行样式表，不是 9 套主题。**

**R2｜三个业务域平行重复。**
sites / docker / services 各自实现了一遍"壳 + 5~6 个布局子组件 + 一个 470 行 Grid"，而布局枚举 `compact|normal|large|list|minimal|rack|map` 是三类共用的。布局 × 类型 = 21 种组合，代码写了 3 份。

**R3｜差异化压在最低价值的轴上。**
主题是"选一次、不再改"的配置项，却吃掉 81% 的样式工程。日常真实摩擦是：找站靠肉眼扫、看不出哪个服务挂了、手机上 div 当按钮、刷新白屏。Theme 上继续加第 10 套 = 死路。

## 1. 目标架构

```
三层分离，越往下越稳定：

① primitives        原始色阶 / 间距 / 字阶 / 动效时长       ~120 行，永不变
② semantic tokens   语义层：--surface-*, --text-*, --border-*, --accent-*
                    主题只允许改这一层                    每主题 ~50 行
③ surface recipes   6 种受控表面工艺：glass / paper / crt / solid / ticket / panel
                    由组件选择，不由主题硬编码             ~200 行，共享
```

**铁律**：组件内只允许出现 ①②③ 的变量，禁止出现 `[data-theme=...]` 前缀——由 stylelint 规则强制。主题再也不能触碰组件内部 class。

**主题 = 数据，不是样式表。**

```ts
// src/themes/presets/receipt.ts —— 全部内容
export default {
  id: 'receipt', label: '运维小票', icon: Receipt,
  surface: 'ticket',                    // 表面工艺
  tokens: { '--surface-bg': '43 2% 90%', '--ink': '225 8% 10%', /* ~40 条 */ },
  texture: { component: ReceiptBackground, motion: 'none', grain: 0.12 },
}
```

9 套主题 = 9 个这样的对象。新增主题成本从"半天 + 认识 124 个类"降到 **10 分钟 + 40 个 token**。

## 2. 分阶段执行

### Phase 0 — 安全网（必须先做，不做后面无法验证）

| 动作 | 产出 | 验收 |
|------|------|------|
| 固定视觉基线 | `scripts/snapshot.mjs`：playwright 截图 9 主题 × 7 布局 × 3 类型 × 桌面/移动 = 378 张 | 基线图入库 `docs/baseline/` |
| 组件测试地基 | 复用已装的 `@vue/test-utils` + happy-dom，测 Grid 渲染条数、Card 点击跳转 URL、布局分支 | `npm run test` 覆盖三个 Grid |
| stylelint 守卫 | 主题文件出现 `.任意组件类` 报错；组件文件出现 `[data-theme` 报错 | `npm run lint` 拦住回流 |
| 体积闸门 | CI 断言 CSS gzip < 60 KB（当前 44 KB，仅防倒退） | CI 红/绿 |

> 为什么先截图：Phase 1/2 都是"看起来必须一模一样"的重构，没有 378 张图对照，改完就是盲改。

### Phase 1 — 主题引擎重写（R1）

**步骤**

1. 从现有 9 套 CSS **反向抽取** token 真值表：把每套的 `--primary / --glass-bg / --text-primary …` 抄成数据对象（机械工作，已定位每主题 41–83 条变量）。
2. 归纳 **6 种 surface recipe**（各主题卡片 chrome 差异全部落在这些维度：圆角、边框、阴影、伪元素装饰、字体、底纹）：
   | recipe | 用于主题 | 特征 |
   |--------|----------|------|
   | `glass` | light / dark / arctic-aurora | 半透明 + blur + 高光 |
   | `paper` | blueprint | 实底浅色 + 细描边 + 网格底纹 |
   | `crt` | crt-terminal | 扫描线 + 绿磷光 + 等宽字 |
   | `solid` | bauhaus | 实色块 + 粗边 + 硬阴影 |
   | `ticket` | receipt | 热敏纸 + 虚线撕边 + 等宽 |
   | `panel` | light-panel / console | 点阵/背光 LED + 暗底 |
3. 重写主题落盘：`themes/registry.ts` 保留，新增 `themes/presets/*.ts`（9 个）+ `themes/surfaces.css`（6 组 recipe，~200 行）。
4. **删除** `assets/styles/themes/*.css` 的 8 个特色主题文件（4,847 → 约 600 行），`_shared.css` 一并删除（它的存在本身就是 R1 的伤疤）。
5. 组件改造：124 个被主题硬改的内部 class 全部改为读 semantic token。`.search-bar-container` 那 80 处重写收敛成一组 `--search-*` token。

**验收**
- 378 张截图与基线逐像素对比（容差 < 2%），9 套主题观感不降级
- CSS 未压缩 **< 100 KB**（预期 60–80 KB）
- 新增第 10 个主题实操演练：只写 `presets/xxx.ts`，不碰任何组件和 CSS，能完整出图
- stylelint 全绿

**回滚点**：Phase 1 独立 PR，`git revert` 即可。

### Phase 2 — 卡片与网格合一（R2）

**步骤**

1. 定义 `<EntityCard>` 一个壳 + 布局渲染表：

```
src/components/entity/
  EntityCard.vue          壳：点击/键盘/链接选择/图标回退
  EntityGrid.vue          替代三个 Grid（filter-bar → group → empty 的统一实现）
  EntityToolbar.vue       搜索 + 分组 + 布局切换 合一
  layouts/default|compact|large|list|minimal|rack|map.vue
  adapters/site.ts        站点 → 统一 ViewModel
  adapters/docker.ts      容器 → ViewModel（含 CPU/内存/网络槽位）
  adapters/service.ts     服务 → ViewModel（含流量/状态槽位）
```

2. ViewModel 契约（三类共用）：

```ts
interface EntityView {
  key: string; title: string; subtitle?: string; icon?: string
  metrics: { label: string; value: string; percent?: number; trend?: number[] }[]
  status?: 'running' | 'stopped' | 'warn' | 'unknown'
  primaryHref?: string
  onActivate?: (el: HTMLElement) => void
}
```

docker/服务特有的走势图、状态灯落在 `metrics[].trend` / `status` 上，布局组件不再区分业务域。

3. 两个 Switcher 合并为 `EntityToolbar` 内的一个弹出层，删除 1,540 行。
4. 删除 `sites/` `docker/` `luckyServices/` 下的 17 个 Card/Grid 文件。

**验收**
- 21 种（3 类 × 7 布局）组合截图对比基线全绿
- 净减代码 **≥ 5,500 行**
- 组件测试覆盖：EntityGrid 分组/多选/搜索/空状态；EntityCard 7 个布局分支
- `layoutScale` 从 `zoom` 改为 `rem` 根字号缩放（`zoom` 在部分浏览器有排版副作用）

**回滚点**：Phase 2 独立 PR。若某布局实在无法归一（`map` 换乘站最可疑），允许它保留独立实现，不强求。

### Phase 3 — 产品形态（R3，才真正"天翻地覆"）

按价值排序，每条可独立上线：

| # | 功能 | 做法 | 价值 |
|---|------|------|------|
| 3.1 | **Ctrl+K 命令面板** | `<CommandPalette>`：模糊搜三类实体 + 分组跳转 + 主题切换 + 设置项直达。不引入依赖，手写 ~150 行（列表 + 键盘游标 + fuzzy） | 取代"肉眼扫 200 个卡片"，最高频动作 |
| 3.2 | **健康墙** | 顶部一条横向状态带：非 running 容器数 / 掉线服务数 / 异常流量；点击即筛到异常项。数据本地已有，零新接口 | 一眼看出"哪里挂了"，当前完全看不出 |
| 3.3 | **URL 状态** | `currentTab` / 分组 / 搜索词 / 布局写进 `location.hash`（`#/docker?g=media&q=plex`）。不引入 vue-router，~60 行 `useUrlState` | 可分享、可收藏、刷新不丢、后退键可用 |
| 3.4 | **PWA + 秒开** | 手写 `sw.js`（~80 行）：shell 预缓存 + 后端 JSON stale-while-revalidate；`localStorage` 存上次 payload，**首帧直接渲染上次数据**再静默刷新 | 消灭加载屏（当前 3 秒兜底黑屏） |
| 3.5 | **键盘可达 + a11y** | 卡片语义化（现在 `div @click`）、焦点环、`aria-label`、`prefers-reduced-motion` 接管动效 | 9 处 aria → 三位数 |
| 3.6 | **移动端重做** | 底部 tab 栏 + 分组横向 chip + 触控目标 ≥ 44px | 当前 81 个 media query 也救不了 |

建议顺序：3.2 → 3.1 → 3.3 → 3.5 → 3.4 → 3.6（3.2 最便宜、体感最强）。

## 3. 风险登记

| 风险 | 概率 | 缓解 |
|------|------|------|
| 特色主题的"味道"在 token 化后消失（receipt 撕边、light-panel 点阵、bauhaus 硬阴影） | 中高 | 6 种 recipe 允许携带受控伪元素装饰（每 recipe 最多 3 条 `::before/::after` 规则），这是唯一 escape hatch；先做 receipt + light-panel 两个最难的验证通过再铺开 |
| `map`（地铁线路图）与其它布局耦合浅，归一化后走样 | 中 | 允许它继续独立；它依赖 `MAP_LINE_COLORS` + 换乘逻辑，是唯一真正"站点专属"的布局 |
| 21 组合视觉回归工作量被低估 | 高 | Phase 0 的 378 张基线是前提；diff 自动生成，人只看差异图 |
| 后端数据契约被改坏 | 低 | `src/types/index.ts` 后端相关字段全程零改动（交接文档已明令），重构只碰 View 层 |
| localStorage 旧配置失效 | 中 | `loadConfig` 加 `configVersion` + 迁移函数；旧 key 保留读一次 |

## 5. 一句话总结

**把 9 份平行样式表换成 9 份数据 + 6 种工艺；把 3 套卡片换成 1 套卡片 + 7 个布局；然后用省下来的一半代码量去做搜索、健康墙和键盘操作。**
