# 开发交接文档

> LightPanel Vue（LuckyLightPanel 二创版）前端项目交接文档。
> 阅读对象：接手继续开发的开发者。数据接口细节另见 [API.md](../API.md)。

---

## 1. 项目定位

Lucky（内网穿透工具）Web 服务的导航面板前端：展示站点导航、Docker 容器、Lucky 服务三类数据，纯前端静态应用，**只读**消费 Lucky 后端提供的 JSON 接口（`/backend/*`），无自建服务端。

关键约束：**`src/types/index.ts` 中与后端契约相关的类型字段（名称/类型）不可随意改动**，否则会与 Lucky 后端断联。

## 2. 工程命令

| 命令 | 说明 |
|------|------|
| `npm install` | 安装依赖（Node ≥ 20） |
| `npm run dev` | 开发服务器 `http://localhost:5173`，`/backend` 代理到 `127.0.0.1:16666/aaa/` |
| `npm run build` | `vue-tsc -b && vite build`，产物 `dist/` |
| `npm run lint` | ESLint 9 flat config（`eslint.config.js`），带 `--fix` |
| `npm run format` | Prettier |
| `npm run test` | vitest 单测（`vitest run`，配置见 `vite.config.ts`） |

包管理器为 **npm**（`package-lock.json`）。锁文件与依赖是清理过的：`radix-vue / motion-v / vue-router / @vueuse/core` 已移除，运行时依赖仅 `vue / pinia / lucide-vue-next`。

## 4. 数据契约

端点全部为 GET JSON，由 Lucky 后端在 `/backend/` 下提供。字段与语义详见 [API.md](../API.md)，类型定义见 `src/types/index.ts`。

| 端点 | 消费方 |
|------|--------|
| `nav.json` | 标题 / Logo / 模块开关 / 服务器背景图 |
| `sites.json` | 站点分组与站点（内/外网链接）|
| `docker.json` / `docker-stats.json` | 容器列表 / 5s 轮询统计 |
| `luckyservices.json` / `luckyservices-stats.json` | 服务列表 / 5s 轮询统计 |
| `api/network-type` | 内/外网判定 |
| `default-config.json` | 服务器下发默认配置（`{ret, config}`）|
| `iconlibs/{path}` | 图标文件 |

开发模式兜底：`vite.config.ts` 中间件先试真实后端（16666），不可达时回退 `public/backend/` 的 mock JSON。

## 5. 状态管理

### config store（`src/stores/config.ts`）

`UserConfig` 持久化到 `localStorage('lightpanel_config')`，默认值见 `DEFAULT_CONFIG`。

| 字段 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `theme` | ThemeMode | `dark` | 8 个主题之一 |
| `background` / `customBgUrl` | string | `ocean` / `''` | 预设渐变 / 服务器图 / 自定义 URL |
| `layout` | LayoutMode | `normal` | 站点区布局 |
| `dockerLayout` | LayoutMode | `list` | Docker 区布局 |
| `luckyServicesLayout` | LayoutMode | `normal` | Lucky 服务区布局 |
| `layoutScale` | number | `1` | 内容区缩放（0.8–1.5）|
| `siteCardSize` | number | `100` | 站点卡片最小列宽 %（70–150）|
| `siteCardShape` | 'square' \| 'rect' | `square` | 站点卡片形状（rect = 左图标右详情）|
| `showDescription / showTime / showSearch / showHeader` | boolean | 见 DEFAULT_CONFIG | 显示开关 |
| `searchEngine` / `customSearchUrl` | string | `bing` / `''` | 搜索引擎 |
| `tabGroups` | TabGroups | `all` | 各分区分组选择（单选/多选）|
| `networkMode` | NetworkMode | `hybrid` | auto / internal / external / hybrid |
| `currentTab` | TabType | `sites` | 当前页签 |
| `detailTextContrast` | number | `100` | 文字对比度 %（80–130）|
| `detailRadiusScale` | number | `100` | 圆角 %（60–150）|
| `detailGlassBlurScale` | number | `100` | 玻璃模糊 %（25–200）|
| `detailGlassOpacityScale` | number | `100` | 卡片不透明度 %（50–150）|
| `detailReduceMotion` | boolean | `false` | 减弱动效 |

关键方法：`updateConfig(key, value)`（通用 setter + 自动保存）、`applyServerConfig`（服务器配置仅在没有本地存储时生效）、`setServerBackgrounds`（优先级：服务器图 > 预设渐变）。

### nav store（`src/stores/nav.ts`）

- `loadNavConfig / loadSitesData / loadDockerData / loadLuckyServicesData`：静态数据
- `loadDockerStats / loadLuckyServicesStats`：5s 轮询（`startXxxPolling`），防重入（上一轮未完成时跳过本次）；stats 按 `key` / `containerName` 双键索引，兼容两种后端格式
- 轮询启停由 `App.vue` 的 `syncPolling()` 统一控制（按当前 tab + 模块启用状态），并监听 `visibilitychange`：页面隐藏暂停、恢复时按当前 tab 重启；`ContentTabs` 仅负责静态数据按需加载，不依赖其挂载，**单 tab 场景（仅启用一个模块）轮询也能正常工作**
- 历史样本：`dockerHistory`（cpu/mem/rx/tx）、`luckyServicesHistory`（in/out），各保留 60 条，供 `Sparkline` 走势图
- `fetchNetworkType`：内/外网识别，失败时降级为 hybrid

## 6. 主题系统

### 架构

- **类型 + ID**：`types/index.ts` 的 `ThemeMode` 与 `THEME_IDS`（唯一顺序来源）
- **注册表**：`src/themes/registry.ts` 的 `THEMES`，为每个主题绑定 label / lucide 图标 / 强调色 / **背景组件**
- **CSS**：`themes/<id>.css` 以 `[data-theme="<id>"]` 作用域覆盖变量与组件细节；在 `main.css` 按序 import
- **背景组件**：每个特色主题一个独立动态背景组件（`common/*Background.vue`），由 `App.vue` 的 `<component :is>` 按注册表渲染
- **消费方**：`AppHeader` 主题下拉、`SettingsPanel` 主题网格、`config.ts` 校验（`THEME_IDS`）全部读注册表，**加主题不用改组件**

### 新增主题步骤（5 步）

1. `types/index.ts`：`ThemeMode` 加 ID + `THEME_IDS` 数组加一项
2. `src/themes/registry.ts`：`THEME_META` 注册 label / icon / color / 背景组件
3. `src/assets/styles/themes/<id>.css`：写 `[data-theme="<id>"]` 覆盖层（先覆盖变量，再覆盖组件细节）
4. `main.css` 顶部 import 新主题
5. （可选）新增背景组件到 `common/` 并在注册表引用

`default.css` 是基线：新主题只需覆盖想改的变量，其余继承。文字类变量统一为 `hsl` 三元组格式（如 `210 30% 96%`），细节调整机制依赖该格式解析，**不要改成十六进制/颜色名**。

### 主题公共层（_shared.css）

`themes/_shared.css` 收敛了 5 个特色主题中**字面完全相同**的组件规则（搜索按钮、页头、滚动条、tab/engine 选项、sparkline 等 19 组），主题文件只保留各自差异。新增主题时若规则与已有主题完全一致，优先放 `_shared.css` 而非复制。

## 7. 布局系统

### 布局模式

`LayoutMode = 'compact' | 'normal' | 'large' | 'list' | 'minimal' | 'rack' | 'map'`

| 布局 | 站点区 | Docker | Lucky | 说明 |
|------|:---:|:---:|:---:|------|
| normal | ✅ | ✅ | ✅ | 卡片详情 |
| compact | ✅ | ✅ | ✅ | 精简卡片 |
| list | ✅ | ✅ | ✅ | 横向列表 |
| minimal | ✅ | ✅ | ✅ | 纯图标 |
| large | ✅ | — | — | 大卡片（仅站点）|
| rack | ✅ | ✅ | ✅ | 1U 机柜前面板 |
| map | ✅ | — | — | 地铁线路图（仅站点）|

### 实现要点

- 卡片组件（`SiteCard` / `DockerCard` / `ServiceCard`）通过计算出的 `layout-xxx` 类名切换变体，模板内 `v-if` 分支渲染
- 网格规则在各 Grid 组件内按布局分开写（例如机柜布局单列堆叠、≥1600px 双列；站点 map/rack ≥1400px 双列）
- 布局切换器：站点用 `common/LayoutSwitcher.vue`；Docker/Lucky 共用 **`common/DataLayoutSwitcher.vue`**（`layout-key` + `accent-rgb` 两个 props，CSS 用 `rgb(var(--accent-rgb) / x)` 变量化主题色）
- 地铁线路图：`SiteGrid.vue` 中 `MAP_LINE_COLORS` 按分组序号取色，`--map-line` 变量绑到分组容器
- 动画（LED 闪烁、hover 缩放）均需尊重 `prefers-reduced-motion`

### 新增布局的触碰面（7 处）

1. `types/index.ts` 的 `LayoutMode` 加值
2. 三张 Card 的 `cardClass` 计算 + 模板变体分支
3. 三个 Grid 的列规则
4. `LayoutSwitcher.vue` / `DataLayoutSwitcher.vue` 的选项 + 预览图
5. 迁移存量配置时无兼容问题（新值直接落库）

## 8. 设置面板与细节调整机制

`SettingsPanel.vue` 分区：主题 / 背景 / 显示（含布局比例、站点卡片尺寸、卡片形状）/ 细节 / 搜索。

- **布局比例**：`--layout-scale` CSS 变量绑定到 `.main-content`，用 `zoom` 属性整体缩放（所有现代浏览器支持）
- **站点卡片尺寸**：`--site-card-min` CSS 变量绑定到站点网格，控制 `minmax` 最小列宽（`SiteGrid.vue` 的 `siteCardMin` 计算）
- **站点卡片形状**：方形（竖排大图标）/ 矩形（左侧图标 + 右侧详情），矩形在 `SiteCardDefault.vue` 内走横排 `card-inner` 分支，网格同时放大列宽
- **细节调整**（`App.vue` 的 `snapshotThemeDetails` / `applyThemeDetails`）：
  1. 快照当前主题的原始 CSS 变量（先清内联覆盖再读 `getComputedStyle`，避免叠乘）
  2. 按用户百分比换算后 `el.style.setProperty` 内联覆盖到 `<html>`
  3. 监听主题变化 → 重新快照 + 重算
  - 文字对比度按当前明暗方向调整（深色主题提亮、浅色主题加深），依赖变量 `hsl 三元组` 格式
  - 不透明度覆盖依赖 `"H S L / alpha"` 格式（正则替换 alpha 段）
- **减弱动效**：`<html>.motion-reduced` 类 + `main.css` 全局规则压平动画/过渡

## 9. 启动流程（`App.vue` onMounted）

1. `loadConfig()`（同步读 localStorage）
2. 并行：`loadNavConfig()` + `fetchServerConfig()`
3. 并行：三区数据预加载 + `fetchNetworkType()`（自动/混合模式）
4. 加载屏兜底：**3 秒硬上限** + 最短展示 500ms + 400ms 淡出（`screen-fade` 过渡）

注意 `LoadingScreen` 与主内容的 `v-if`/`v-else` 配对（原为 `v-else`，改动时要保持配对）。

## 11. 代码约定与注意事项

- **ESLint**：9 flat config；关闭了 4 条纯排版 vue 规则（`max-attributes-per-line` 等），新增代码保持与现网风格一致即可
- **TypeScript**：`strict` + `noUnusedLocals`，Vue 组件用 `<script setup>` + `defineProps` 泛型
- **Vue 陷阱**：从 store 解构的 ref 在模板中自动解包；嵌套对象里的 ref（如 `configStore.config.xxx`）在模板中需注意——本项目 SettingsPanel 直接读 `configStore.config.field`（store 本身是 reactive 对象，可解包）
- **CSS 变量约定**：颜色一律 `hsl` 三元组字符串（`--xxx: 210 30% 96%`），使用时 `hsl(var(--xxx))`；带透明度的用 `"H S L / 0.4"` 格式。细节调整机制依赖此约定
- **动效**：新动画必须加 `prefers-reduced-motion` 降级
- **图标**：一律 `lucide-vue-next`（勿加 FontAwesome 图标类，CDN 已改非阻塞加载）
- **不要引入重型依赖**：运行时依赖刻意保持 3 个，新增前先想清楚

## 12. 已修复问题

- **单 tab 场景轮询不启动**：轮询控制原挂载在 `ContentTabs`（`v-if="tabs.length > 1"`），仅启用一个模块时组件不渲染 → 统计/走势图空白。已移至 `App.vue` `syncPolling()`
- **轮询无防重入**：后端响应慢时请求并发叠加，已加 in-flight 跳过
- **Docker stats 键错位隐患**：原仅按 `containerName` 索引，已改为 `key` / `containerName` 双键
- **死代码**：`loadAllData()` 无调用，已删除
- **页面隐藏轮询不停**：已加 `visibilitychange` 暂停

## 13. 已知问题与后续建议

- **测试覆盖偏小**：站点链接纯函数已有 17 个 vitest 用例（`src/utils/siteLinks.test.ts`），Docker/Lucky 的链接逻辑尚未抽纯函数、未覆盖
- **站点卡片配置仅影响站点区**：`siteCardSize/siteCardShape` 目前只作用于站点模式，Docker/Lucky 无对应配置，如需可照抄
- **主题 CSS 仍有冗余**：各主题 600+ 行覆盖层，跨主题相似但非完全相同的规则尚未收敛，只处理了字面重复部分
- **轮询**：统计接口 5s 全量拉取，量大时可考虑 diff 增量或服务端推送
